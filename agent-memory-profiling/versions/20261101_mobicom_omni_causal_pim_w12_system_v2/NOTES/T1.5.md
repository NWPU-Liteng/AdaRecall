# T1.5 接口理解

## 见证值来源

- `omni_proof_grounding.py` 的默认 `WITNESS_SCHEMA` 不含 `values`，只有
  `witness_values: on` 时主链改用 `WITNESS_VALUES_PROMPT` 与
  `WITNESS_VALUES_SCHEMA`。因此关闭开关时，模型输入、输出 schema 与见证身份哈希保持原合同。
- `values[]` 每项包含 `name`、`type`、`value`、`record_id`、`text_index`。`value` 必须逐字
  出现在所引用的 text atom 中，复用与 binding 相同的 `quote_anchor()` 校验；最多 8 项。
- 无原文定位的值被丢弃到 `discarded_optional_fields` 的 `unlocated_value`，不会使整个
  见证失败。接受的值写入 `values` 与 `value_sources`，其来源 object 同时进入
  `object_ids`，并参与见证身份哈希。
- 只有非空时才输出 `values`/`value_sources`，避免默认路径增加元数据。多见证的 branch
  规范化也保留 values/value_sources，且去重键包含 values。
- 主链记录实际使用的三个构造 prompt 与 values schema 的 sha256；默认关闭时不写该字段。

## 类型化值

- `typed_values.Interval` 是闭区间，单位为 `day`、`second`、`number` 或 `count`。
  日期用 `date.toordinal()`，datetime 用“ordinal 天数 + 当日秒数”。
- 绝对日期支持 ISO、`YYYY年M月D日`、无年份 `M月D日` 与英文月份名。无年份日期在 session
  同年时取该年；session 跨年时按计划返回整年 `[起始年 1 月 1 日, 结束年 12 月 31 日]`。
  非法月日返回 `None`，不猜测。
- 相对日期按 session 可见区间平移。例如“昨天”是
  `[visibility_start-1d, visibility_end-1d]`，不把 session 区间误当成逐轮时刻。
- 数字支持阿拉伯数字、千分位和中文数字。时长支持天/周/月/年；月按 `[28,31]` 天/月，
  年按 `[365,366]` 天/年展开。无法解析的输入返回 `None`。

## 运算执行

- `operation_executor.execute()` 按 query contract 的 DAG 顺序执行
  difference、comparison、selection、aggregation。后续 operation 可读取前序结果。
- difference 为 `[a.lo-b.hi, a.hi-b.lo]`，输入单位必须一致。comparison 在区间不相交时
  给出确定顺序，相交时为 `undetermined`。selection 默认 argmax；问题片段含最早、最少、
  最小等常量词表中词汇时 argmin，只有唯一确定才可执行。
- aggregation 只统计该 demand 已接受见证中不同 binding 值的下界，不声称精确总数。
- 任一输入缺失、值不可解析、单位冲突或排序不唯一时返回 `not_executable` 并保留原因。
- 主链在见证验证完成后、预算渲染前执行运算，因此追加后的程序结果会计入 Reader 输入预算；
  `render_operation_plan()` 的原始文本计划保持不变，程序结果只追加在其后。
- `report_run_stats.py` 新增 `operation_execution` 段，输出有执行字段的行数、操作总数、
  status 分布、kind 分布和 kind×status 交叉分布。

## Golden 实跑

- 关闭配置运行 6 题到 `regression/golden_v2_t15_off`，6 行均 `status=ok`。与
  `regression/golden_v1_run1` 比较：`status=pass`、`failures=[]`、
  `nondeterministic_differences=[]`。run stats 中
  `operation_execution.rows_missing=6`、`total=0`，符合默认关闭行为。
- 开启 `witness_values: on` 与 `operation_executor: on` 运行同批 6 题到
  `regression/golden_v2_t15_on`。与关闭配置及原始 golden 比较均为 `status=pass`、
  `failures=[]`、`nondeterministic_differences=[]`。6 行都记录了三个见证构造 prompt 与
  values schema 的 sha256，且 `operation_execution.rows_with_execution=6`、`rows_missing=0`。
- 该 golden 批次的 6 道题均为 contextual 或未产生 query operation，因此
  `operation_execution.total=0`。这不是执行器失败；只说明该批数据没有派生运算。
- 为覆盖真实主链运算路径，按可见问题文本选择 label-free 的 `0_q_645` 做单题 smoke。该题
  产生一个 `difference` operation，程序结果明确追加到 Reader 计划。由于检索到的 d0 见证
  被拒、d1 见证没有可解析 values，执行器返回
  `not_executable`，原因为 `d0 缺少可解析值；d1 缺少可解析值`，没有伪造时间差。
- smoke 的 run stats 为：`rows_with_execution=1`、`total=1`、`status.not_executable=1`、
  `kind.difference=1`、`difference.not_executable=1`。`ok` 分支、DAG 与渲染由合成测试覆盖。
- 所有 golden 与 smoke 只使用 GPU 0、1；未使用 GPU 2、4。运行期间 GPU 2 可能被其他进程
  使用，与本任务无关。
