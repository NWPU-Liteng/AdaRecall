# T0.1 接口理解

- v1 位于 `versions/20261031_mobicom_omni_causal_pim_w12_system_v1`。代码目录为
  `scripts/`、`pim_backend/`、`configs/`、`tests/`、`third_party/` 和 `docs/`；
  `artifacts/` 与 `results/` 属于数据、索引或运行输出，不复制。v2 通过配置中的绝对路径
  引用 v1 的 prepared 数据和 proof index。
- `scripts/run_main_experiment.py --mode launch` 读取配置的 `paths.cohort`，`--users`
  缺省时运行 cohort 中全部用户；每个用户由 `run_proof_mainline.py` 写入
  `paths.run_root/user_<id>_shard_0.json`。`serving.question_ids_file` 是全局文件，不能用于
  为不同用户指定不同题集，因此 golden cohort 需要缩减为每个用户 3 个 question_id。
- `run_proof_mainline.py` 的最终题级结果位于顶层 `rows`。回归要求比较的字段中，
  `answer` 在 row 顶层；`accepted_object_ids`、`proof_status`、`selection_mode` 和
  `query_contract` 位于 row 的 `proof_plan` 内。候选 record_id 按 demand 保存于
  `row.grounding_frontier.records[*].demand_id/base_record_id`，同一 demand 保持原顺序。
- golden 集从 `development` split 取用户 `0`、`1`；每个用户对 cohort 内 development
  question_id 做字符串字典序排序，取前 3 个。实际为：
  - 用户 0：`0_q_1033`、`0_q_109`、`0_q_1162`
  - 用户 1：`1_q_104`、`1_q_1166`、`1_q_1188`
- v1 golden 运行使用 v1 代码、v2 regression 配置和 v2 输出目录；不会写入 v1 目录。
  v2 golden 运行使用复制的 v2 代码、同一配置契约和独立输出目录。
