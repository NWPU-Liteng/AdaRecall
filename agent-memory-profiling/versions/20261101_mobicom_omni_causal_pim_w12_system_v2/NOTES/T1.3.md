## omni_graph.json

- 顶层是按用户排列的数组，每个图含 `person_id`、`sessions`、`atoms`、`hyperedges`、
  `dependencies`、`image_audit`、`label_free` 等字段。
- session 字段：`session_id`、`event_id`、`start_time`、`end_time`、`ordinal`、
  `image_refs`。`image_refs[]` 含 `raw`、`normalized`、可选 `resolved`、`status`。
- atom 字段：`atom_id`、`event_id`、`session_id`、`atom_kind`、`ordinal`、
  `session_ordinal`、`turn_ordinal`、`visibility_start`、`visibility_end`、`role`、
  `content_type`、`content`、`image_refs`。
- 例：session `{"session_id":"0_0","event_id":"0","start_time":"2025-01-01 08:30:00",
  "end_time":"2025-01-01 10:30:00","ordinal":0,"image_refs":[...]}`；
  atom `{"atom_id":"0_0:turn:0","event_id":"0","session_id":"0_0",...,"content_type":"text"}`。

## source.json

- 顶层字段为 `schema=source-object-container-v2`、`person_id`、`containers`、`objects`、
  `records`、`unresolved_sources`。
- text object：`object_id`、`kind=text`、`atom_id`、`session_id`、`role`、`ordinal`、
  `source_sha256`、`text`、`raw_text`、`source_span`、`time`。
- image object：`object_id=image:<sha256>`、`kind=image`、`source_sha256`、`image_ref`、
  `sources[]`；每个 source 含 `atom_id`、`session_id`、`role`、`ordinal`、`time`、
  `image_ref`。
- object id 与最终输出的 `proof_plan.accepted_object_ids` 同一命名空间。text object 可直接
  映射到原 session；image object 的 `sources[]` 给出全部可观察来源 session，sha256 位于
  `source_sha256`，并与 `object_id` 后缀一致。

## 可映射层级与统计口径

- session 是可靠的标注粒度：`source_session_ids` 是准备阶段已解析的规范 session 证据。
  最终 session 集合由 `proof_plan.accepted_object_ids` 经 source object 映射得到；text
  object 取其 `session_id`，image object 取所有 `sources[].session_id`。
- 图片是可可靠映射的独立粒度：`evidence_image_refs` 经 source image object 的
  `raw/normalized/resolved` 引用精确匹配到 `source_sha256`，再与最终 accepted image
  object 的 sha256 求交。不使用 basename 猜测，不按路径前缀猜测。
- `raw_evidence` 只有 event 编号和解释，没有 `atom_id`，解释也不是可假设逐字相等的 atom
  content。因此不计算 atom 级或 event 级召回，避免编造更细映射。
- `evidence_recall_session` 与 `evidence_recall_image` 分别给出总表、按 `proof_status`、
  按 `question_type`、以及二者交叉分组。每题保存命中数、标注数、映射失败和原始集合。
  没有对应标注的题不计入该指标的均值分母。
- 映射失败按 `source_session_ids` 中不在该用户图中的 session，以及无法映射到 source
  sha256 的图片引用计数。脚本还会校验 run shard 的 `index_sha256` 与所用 source index。
- `candidate_recall_session` 依赖 T3.1 的候选 dump；评测脚本尚未接入该 dump，本任务不伪造
  候选池召回，输出 `status=skipped_no_candidate_dump`。
- `source.json` 不在 prepared 目录内，run 输出也只记录 `index_sha256`。脚本支持可选
  `--index-root`；未给出时只在 labels 同级/上级的约定 `indexes_final` 或 `indexes` 目录
  查找唯一匹配的 `proof_index_user_<id>/source.json`，找不到或有歧义时 `raise`，不静默猜测。
- 本脚本以 `eval_` 开头，仅离线读取标签；serving 代码不导入该脚本。

# T1.3 执行结果

- 新增 `scripts/eval_evidence_recall.py`。默认命令为
  `eval_evidence_recall.py <run_dir> --labels <prepared>/labels.jsonl`；source index 可从
  prepared 同级的 `indexes_final/proof_index_user_<id>/source.json` 唯一发现，也支持显式
  `--index-root`。输出默认写到 `<run_dir>/evidence_recall.json`。
- 脚本校验：run shard `complete=true`、`index_sha256` 与 source index 一致、prepared audit
  中 labels/graph 哈希一致、graph 标记 `label_free=true`、accepted object 均存在于 source
  index。任一不满足都会 `raise`，不回退到路径或 basename 猜测。
- session 指标以 `source_session_ids` 为分母；accepted text/image object 经 source object
  映射到 session。image 指标以 `evidence_image_refs` 精确映射出的 sha256 为分母。映射失败的
  session 和图片引用分别计数，不进入可映射召回分母。
- 输出包含总体指标、逐题明细、`by_proof_status`、`by_question_type` 及二者交叉分组。每题保留
  labeled/accepted session 与 image sha256、命中数和失败明细。`raw_evidence` 没有 atom_id，
  因此 atom/event 级明确标为 `not_evaluated`。
- `candidate_recall_session` 为 `skipped_no_candidate_dump`；本任务尚未接入后续 T3.1 的
  候选池 dump，故不伪造该数值。
- 合成测试覆盖：text/image 经 source object 映射、图片多 source session、两个分组层级与交叉
  分组、无标注分母跳过、无法映射的 session/图片、partial 文件忽略、index 哈希不一致、
  incomplete shard、缺失标签、未知 accepted object、冲突图片引用及 source root 缺失。
- 定向测试：`pytest -q tests/test_eval_evidence_recall.py tests/test_report_run_stats.py
  tests/test_label_isolation.py`，结果 `18 passed`。
- 完整 CPU 测试：`pytest -q tests -m "not gpu"`，结果 `715 passed, 3 failed`。三个失败与
  T0.3/T1.1/T1.2 记录一致，属于既有基线问题：缺少
  `artifacts/hyperpim_sc_trace_v1`、旧 judge 状态字符串断言、重复 demand 预期差异。

  图片标注 5 个、命中 1 个，pooled recall `0.2`，逐题均值 `0.166667`；有图片标注的题为
  `1_q_104`（`0/1`）、`1_q_1166`（`1/2`）、`1_q_1188`（`0/2`）。
