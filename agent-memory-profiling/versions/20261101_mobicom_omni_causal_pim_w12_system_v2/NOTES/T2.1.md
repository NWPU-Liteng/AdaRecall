# T2.1 接口理解

## v1 位平面编码

- v1 的 `quantize_signed_groups()` 使用对称按组量化，12-bit 码值范围为
  `[-2047, 2047]`，以 `int16` 承载。
- `W12BankLayout` 每个逻辑行把 12 个平面连续打包；写入时 plane `p` 取
  `(codes >> p) & 1`，即 v1 bank 行内 plane 0 是 LSB。解包时组合为无符号 12-bit 值，
  再对 `>= 2048` 的值减 `4096`，因此最终语义是 12-bit two's complement。
- T2.1 新模块按计划改为全局 plane-major：数组形状 `[bits, rows, ceil(cols/8)]`，
  plane 0 是符号位，权重 `-2^11`；plane `p >= 1` 的权重为 `2^(11-p)`。
  打包仍使用字节内 big-endian bit order。

## 量化与打包

- `quantize_plane_major(w)` 将输入转成 float32 NumPy/Torch 后直接调用 v1
  `quantize_signed_groups(..., weight_bits=12)`，不复制量化公式；只把返回的码值重排为
  符号位在前的 plane-major。
- `from_codes()` 校验码值范围、group 对齐、scale 形状与正值，并生成稳定的
  `codes_sha256`。哈希包含 bits、group size、形状和所有 int32 码值。
- `decode_codes()` 按 plane 0 符号位重建有符号 int32 码值，与 `from_codes()` 输入逐位相等。

## 渐进上界与剪枝

- 输入 activation 统一转 float64。每组预计算
  `P_g=sum(max(x,0))` 与 `N_g=sum(min(x,0))`。
- 第 m 轮部分码值为符号位加已读正权重平面；剩余量
  `R_m=2^(12-m)-1`。下界 `S_i^(m)+R_m*scale_i·N`，上界
  `S_i^(m)+R_m*scale_i·P`。
- 幸存区间下界第 k 大值为 `tau_k`；仅当 `U_i < tau_k-eps` 时剪除，
  `eps=eps_rel*max(1,max|U_i|)`。幸存数不大于 k 时不剪枝。
- 最终只对幸存行解码全部平面并用同一 `reference_scores()` 计算精确 float64 得分，
  按 `(-score, index)` 稳定排序。
- `row_mask=False` 的行不进入上界、读取或最终排序。允许行数为 0 时 raise；
  允许行数小于 k 时返回全部允许行。
- 统计包含计划要求的 `rounds`、`plane_row_reads`、`full_plane_row_reads`、
  `weight_bytes_read`、`weight_bytes_full`、`scale_bytes_read`，并额外记录幸存行数、
  总平面数与码值哈希。

# T2.1 执行结果

## 实现

- 新增 `pim_backend/progressive_topk.py`：`PlaneMajorMatrix`、
  `quantize_plane_major`、`from_codes`、`decode_codes`、`reference_scores` 与
  `progressive_topk`。
- 打包顺序为全局 plane-major、plane 0 符号位；v1 的量化函数与索引文件没有被修改。

## 测试

- 新增 `tests/test_progressive_topk.py`，覆盖：
  - v1 量化码值 round-trip 与 `codes_sha256` 稳定性；
  - 参考得分与独立 grouped GEMM 一致；
  - 200 组随机精确性用例，覆盖 rows `1/7/300/5000`、cols `128/1024/2560`、
    k `1/5/48/80`、高斯/Student-t 分布、负 activation；
  - 重复行、全零行和索引平局排序；
  - row mask、零允许行、允许行数小于 k；
  - 三种 plane schedule：`[1]*12`、`[4,2,2,2,2]`、`[12]`；
  - 每轮每个幸存行的上下界成立；
  - `plane_row_reads <= full_plane_row_reads` 与字节读取计数。
- 定向测试：`pytest -q tests/test_progressive_topk.py`，结果 `8 passed`。
- 完整 CPU 测试：`pytest -q tests -m "not gpu"`，结果 `747 passed, 3 failed`。
  三个失败与既有基线一致：缺少 `artifacts/hyperpim_sc_trace_v1`、旧 judge 状态字符串断言、
  重复 demand 预期差异。

## 边界

- 当前模块是 Host/Numpy 参考实现，不声称实际 bank-PIM 时序或能耗。
- 精确性只相对于同一份量化码、同一 float64 参考计算路径；不是对原始 BF16/FP32 权重的
  无损还原承诺。
