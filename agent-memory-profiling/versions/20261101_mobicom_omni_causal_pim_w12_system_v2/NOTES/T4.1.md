# T4.1 精确视觉特征缓存

## 接口理解

- Reader 是 `Qwen3_5ForConditionalGeneration`，实际视觉边界在内层
  `Qwen3_5Model.forward()`：先调用 `self.get_image_features(pixel_values,
  image_grid_thw, ...)`，再把返回的 `pooler_output` 拼接、按 image placeholder
  scatter 到 `inputs_embeds`，然后执行 3D position computation 和 language model。
- 外层 `Qwen3_5ForConditionalGeneration` 也有 `get_image_features()` 代理方法，但
  forward 实际调用内层 `self.model.get_image_features()`。因此运行时优先解析
  内层边界；主流程显式传入 `reader.model`。
- `get_image_features()` 是干净注入点。缓存其整批 `pooler_output` 不改变文本
  embedding、3D position ids、image-token scatter 或 language model 的执行顺序。
- 视觉 attention 使用 packed `cu_seqlens`。此前 GPU 探针显示，把两张图片拆成两个
  `get_image_features()` 调用与整批编码并非逐位相等，特征最大绝对差分别为
  `0.7109375`、`0.625`，后续 logits 最大绝对差 `1.03125`。因此没有实现逐图缓存，
  只复用 ordered-whole-batch 结果。
- 现有 `omni_visual_feature_store.py` 的键包含有序图片 sha256、pixel tensor/grid
  摘要、dtype、merge size、model identity 和 processor identity；值为 CPU bounded
  LRU，命中时复制回原设备。

## 实现

- 新增 `scripts/omni_visual_feature_cache_runtime.py`：
  - `vision_feature_cache=off` 时在读取任何模型文件前直接返回 `None`，默认路径不增加
    哈希计算、缓存对象或输出字段。
  - 默认容量固定为 `512 * 1024**2` 字节；这是本次实现的进程内 CPU 上界，未做容量
    敏感性调优。
  - model identity 哈希 Reader 目录下的 `.json`、`.safetensors`、`.txt`、`.py`、
    `.jinja` 文件；processor identity 额外绑定 processor/image_processor 的运行时
    `to_dict()` 以及 processor 配置文件哈希。
  - 激活时优先选择真正持有 `get_image_features` 的内层模块；无图片请求不 patch 模型，
    只记录 `no_image_requests`。
- `run_proof_mainline.py` 仅在最终 Reader generation 的 `greedy()` 外层激活缓存；
  `off` 时使用原 `greedy()` 路径，不写出新增字段。
- `on` 时题级输出 `vision_feature_cache` 的 hit/miss/eviction/bypass/integrity 增量、
  resident/peak bytes、entries 和有序图片 sha256；用户级顶层输出容量、完整计数器、
  Reader/processor identity、key scope 与边界说明。
- `--capture-reader-inputs` 现在同时写 `*.pt` 和同名 metadata JSON，记录有序图片
  sha256 与 input_ids 摘要，供独立 prefill qualification 使用。
- 新增 `scripts/qualify_visual_feature_cache.py`。每题依次执行无缓存 prefill、冷缓存
  miss、热缓存 hit；使用生产同款 `use_cache=True, logits_to_keep=1`，并以
  `torch.equal` 比较末位 next-token logits。报告还强制要求冷路径恰好 miss 1、
  热路径恰好 hit 1，否则 `complete=false`，避免“恰好没走缓存”的假阳性。

## GPU 验证：真实含图题目

- 仅使用 RTX 3090 GPU 0；未使用 GPU 2、4。三个 development 题目的最终 Reader 输入
  由当前 v2 代码在默认 `vision_feature_cache=off` 下捕获，不读取 labels：
  - `0_q_1033`：2 图，4417 input tokens。
  - `0_q_1162`：3 图，4689 input tokens。
  - `1_q_1166`：2 图，4440 input tokens。
- 捕获后的 input token 数、图片数和有序图片 sha256 与 v1 对应行一致。
- 报告：
  `regression/golden_v2_t41/prefill_qualification.json`。三题的冷 miss 与热 hit
  logits 均满足 `torch.equal(uncached, cached) == true`，最大绝对差均为 `0.0`；
  三次预热累计 `3 hits / 3 misses / 7 image_hits`，`resident_bytes=8862720`、
  `peak_resident_bytes=8862720`、`capacity_bytes=536870912`，无 eviction、rejection、
  bypass 或 integrity failure。
- 主流程烟雾测试：
  `regression/golden_v2_t41/results/user_0_cache_on_smoke.json`。单题 `0_q_1033`，
  `vision_feature_cache=on`，`max_new_tokens=1`；完成状态为真，题级 miss 1、无 bypass，
  resident `2580480` bytes，顶层 identity 与 qualification 完全一致。该运行只验证
  接入和输出契约，不用于答案质量或延迟结论。
- 第一次 qualification 曾把外层代理方法当作激活边界，导致缓存计数为 0 但 logits
  仍相等。该无效报告保留为
  `regression/golden_v2_t41/prefill_qualification.cache_not_exercised.json`；运行时已
  改为优先内层边界，并加入 cold miss/warm hit 的 exercised 门禁。

## 边界

- 该缓存是进程内精确复用，不持久化到磁盘；跨进程无法命中。
- 三个题目只覆盖 development 的 2/3/2 张图输入，不能外推到更大图片集合、其他
  分辨率或视觉模块被量化/替换的 Reader。
- 主流程烟雾测试只有冷 miss；热 hit 的逐位等价来自捕获输入 replay，不包含在线
  retrieval、decode 或端到端延迟结论。
- 512 MiB 容量未调优；本次实验没有触发容量压力或 LRU eviction。
- 没有实现逐图视觉缓存，避免改变 packed visual attention 的数值路径。
