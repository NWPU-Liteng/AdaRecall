# T4.2 对象复用统计

## 接口理解

- `run_dir/user_*_shard_*.json` 的顶层包含 `person_id`、`question_ids`、`shard_index`、
  `shard_count`、`reader_model` 和 `rows`；`.partial.json` 不是完整结果，必须忽略。
- 题级 `row["materialized_object_ids"]` 是该题最终送入 Reader 的唯一对象集合，顺序与
  run 记录一致；`row["materialized_object_ids"]` 和 `proof_plan["accepted_object_ids"]`
  指向同一组对象。
- 文本对象 ID 为 `text:<atom_id>`。`proof_plan["accepted_atom_ids"]` 与
  `proof_plan["assessment"]["text"]` 一起给出 materialized 文本；按
  `[session][atom_id][` marker 的文本位置排序并切段，可以用 Reader tokenizer 逐对象
  计数。development 的 2 个默认回归用户、6 道题上，逐对象 token 求和与
  `assessment["text_tokens"]` 完全一致。
- 图片对象 ID 为 `image:<image_sha256>`。run row 只保留
  `assessment["visual_tokens"]` 总数，没有逐图 token；若提供对应
  `proof_index_user_*/image_costs.json`，则使用其精确值，并校验逐图求和等于 run 总数。
  缺少该文件时只能把 row 的视觉 token 总数按图片数均分，并在报告中标记为估计。
- 多 shard 时 `request_index` 是 shard 内序号。完整顺序应由同一用户的
  `shard_index/shard_count/question_ids` 按 `shard_index = full_index % shard_count`
  轮转重建。
- 统计只读取 run 输出和 label-free token/image 成本，不读取 labels、golden answer、
  题型或标注证据。

## 实现边界

- `shard_index` 必须是 `[0, shard_count)` 内的整数；同一 shard 的 `request_index`
  必须是不重复的非负整数，row 的 `person_id` 必须与 shard 顶层一致。`.partial.json`
  和 `capacity_capture_only = true` 的输出均拒绝读取。
- 文本对象成本包含其 render marker 以及该对象到下一个对象 marker 之前的边界字符。
  这种切分保证逐对象成本之和等于 `assessment["text_tokens"]`。若同一文本对象在不同
  题中恰位于末尾，后续是否还有对象会改变其末尾换行归属，因此可能产生 1 token 的
  边界差异；报告在 `inconsistent_object_token_costs` 中显式记录，不静默抹平。
- 报告同时给出每个用户的完整题序和逐对象成本，便于复核；`ideal_object_kv_reuse` 与
  LRU 数字都是独立对象 KV span 假设下的分析上界，不是实测收益。
