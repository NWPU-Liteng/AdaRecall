# T4.3 接口理解

- T1.1 的 trace schema 为 `omni-serving-workload-trace-v1`，目录布局为
  `trace/<person_id>/<question_id>.json`。每份 trace 的 `stages` 包含九个阶段。
- 只有 Reader 阶段带 `(prefill_tokens, decode_tokens, n_images)`：
  `contract_parse`、`witness_construct`、`answer_prefill`、`answer_decode`。
  `witness_construct` 是条件阶段，contextual 题可能没有该条目；其余非 Reader 阶段
  三个字段均为 `null`，不能伪造为零。
- `answer_prefill` 的 `decode_tokens` 为 0；`answer_decode` 的 `prefill_tokens`
  是该 Reader 调用的完整输入长度，`decode_tokens` 是实际生成 token 数。同一题的两个
  阶段因此不是同一份 workload，不能互相替代。
- trace 已含 `question_sha256`，但没有模型或手机参数。真机重放需要宿主侧 manifest
  保存 trace 来源哈希，执行脚本再单独记录被推送的模型、二进制和 manifest 哈希。
- `llama.cpp` 的 `llama-bench` 使用 `-p`/`-n` 指定 prompt/generated token 数，通用
  文本二进制没有可移植的图片输入接口。因此 manifest 保留 `n_images`；执行脚本默认
  跳过 `n_images > 0` 的组合并明确记录，只有用户显式选择
  `--include-image-text-only` 时才把其文本 token 长度送进 bench。该选项不表示图片
  编码器已被重放。
- 本任务只生成脚手架和空结果目录，不运行手机、不采集延迟、不生成任何性能数值或
  加速比；模型是否被特定 llama.cpp 构建支持由用户在设备上实际运行确认。

## 执行结果

- 新增 `device/replay_from_trace.py`：递归读取 T1.1 trace，校验 schema、用户/题目标识、
  `question_sha256`、九个已知阶段及 Reader workload 字段；输出逐阶段 workload 列表和
  按 `(prefill_tokens, decode_tokens, n_images)` 去重的组合。manifest 记录 trace 文件、
  trace schema 与生成脚本的 sha256，`measurements` 固定为空。
- 新增 `device/android_bench.sh`：模型、二进制和线程数均为必填参数；通过 adb 推送模型、
  `llama-bench` 和 manifest，并逐组合调用
  `llama-bench -m ... -p ... -n ... -t ... -r ... -o json`。原始 stdout/stderr、
  `commands.tsv`、adb 日志和三份输入哈希均保留在输出目录。
- 图片组合默认跳过并记为 `skipped_image_encoder`；只有显式
  `--include-image-text-only` 才按文本长度运行并记为 `ok_image_text_only`，不会声称
  图片编码器已被重放。任何 llama-bench 调用失败都会保留原文件并以非零状态退出。
- 使用现有 T2.4 trace 生成验证用 manifest：1 份 trace、4 个 Reader workload、
  4 个唯一长度组合、0 个图片组合；输出位于
  `regression/golden_v2_t43_replay/replay_manifest.json`，其中 `measurements = []`。
- 定向测试：`tests/test_replay_from_trace.py`，结果 `7 passed`。其中用假 adb 验证了
  推送、`-p/-n/-t/-r` 参数、默认图片跳过、显式 text-only 模式和结果元数据。
- 完整 CPU 回归：`pytest -q tests -m "not gpu"`，结果 `820 passed, 3 failed`。三个失败
  仍为既有基线（缺少 `artifacts/hyperpim_sc_trace_v1`、旧 judge 状态字符串、重复 demand
  预期差异），本任务未新增失败。
- 未运行手机、未调用真实 `adb`、未产生任何设备性能测量；本任务不提供加速比或能耗结论。
