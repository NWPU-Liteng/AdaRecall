# T1.4 接口理解

## 时间与数据边界

- `omni_prepare.py` 的规范时间格式为 `%Y-%m-%d %H:%M:%S`，`parse_time()` 同时修复
  `YYYY-MM:DD` 的月日分隔符。T1.4 直接复用该函数，不另写时间解析器。
- graph session 实际字段是 `start_time`/`end_time`；atom 字段是
  `visibility_start`/`visibility_end`。`visible_sessions()` 以 session 的完整结束时间为准，
  兼容 `visibility_end` 与现有 `end_time`；两者同时存在但不一致时 `raise`。
- 当前 prepared 数据没有查询发布时间，`manifests.jsonl` 中所有
  `effective_timestamp` 都等于该用户完整历史的 `history_end`。因此当前 golden 数据上，
  `as_of_question` 与 `history_end` 的可见集合相同；不能用这批数据声称存在真实在线时点效应。
  T1.4 仍严格实现 `session_end_before_question`，合成测试使用不同 cutoff 覆盖未来历史。

## 可见性规则

- `visible_sessions(graph, question) -> frozenset[str]`：仅当
  `session.end <= question.effective_timestamp` 时 session 可见；边界取等号。
- text object 由所属 `session_id` 决定；image object 只要有一个 `sources[].session_id`
  可见即可物化。图片 header 与物化 hint 只保留可见 source，避免把未来来源暴露给 Reader。
- `materialize(..., visible_session_ids=...)` 遇到任一不可见 object 直接 `raise`。参数默认
  `None`，保持 v1/history_end 的旧调用行为。

## Serving 接入

- 主链没有名为 `dense_topk` 的独立函数；稠密检索是 `vectors @ demand_vector` 内联矩阵乘法。
  因此复用现有 `--visible-index-mode` 的 filter/mask 路径，将 as-of session 集合并入
  `visible_session_ids`，再过滤检索记录和向量。见证候选、frontier、join 与物化都来自该
  可见集合，没有新增平行检索实现。
- as-of 与 persistent replay 同时启用时取两者 session 集合交集，避免任一机制放宽可见性。
- 输出行新增 `visibility_protocol` 与 `n_visible_sessions`。history_end 下
  `n_visible_sessions` 为完整 graph session 数；as-of 下为截止问题时刻的可见数。
- 可见 session 数为 0 时，在 query parser 之前直接写
  `answer=""`、`status="no_visible_history"`、`n_visible_sessions=0`，不执行任何 Reader
  推理，也不进入检索或物化。
- `report_run_stats.py` 新增 `visibility` 段，统计 protocol、status、
  `no_visible_history` 数量与 `n_visible_sessions` 分布。
- `eval_evidence_recall.py` 读取 prepared `manifests.jsonl`，用同一
  `visible_sessions()` 计算每题标注 session 的未来可见性；输出
  `future_history_evidence.questions_depending_on_future_history` 及逐题
  `invisible_labeled_session_ids`。该统计只在离线 eval 中读取标签。

# T1.4 执行结果

## 实现

- `scripts/omni_proof_sources.py`：新增 `visible_sessions()`、
  `object_is_visible()`；`materialize()` 新增可选 `visible_session_ids`，统一执行对象可见性
  拒绝并过滤图片 observable sources。
- `scripts/run_proof_mainline.py`：增加 as-of 可见集计算、检索与物化约束、零可见历史短路、
  行级字段与 `no_visible_history` 输出。
- `scripts/report_run_stats.py`：增加 visibility 统计及 Markdown/JSON 输出。
- `scripts/eval_evidence_recall.py`：增加 manifests 读取和未来历史依赖统计。

## 测试

- 新增 `tests/test_visibility_as_of.py`，覆盖 session 结束边界、空可见集、非法时区/格式、
  图片多来源可见性、不可见物化拒绝、图片 header/hint 只含可见来源。
- `tests/test_report_run_stats.py` 覆盖 protocol/status/零可见历史/n_visible 分布。
- `tests/test_eval_evidence_recall.py` 覆盖标注证据 session 位于问题时刻之后时的逐题与总体
  计数。
- 定向测试：
  `pytest -q tests/test_visibility_as_of.py tests/test_report_run_stats.py
  tests/test_eval_evidence_recall.py tests/test_persistent_session_replay.py
  tests/test_extensions_config.py`，结果 `31 passed`。
- 完整 CPU 测试：`pytest -q tests -m "not gpu"`，结果 `723 passed, 3 failed`。三个失败与
  既有基线一致：缺少 `artifacts/hyperpim_sc_trace_v1`、旧 judge 状态字符串断言、重复 demand
  预期差异。
