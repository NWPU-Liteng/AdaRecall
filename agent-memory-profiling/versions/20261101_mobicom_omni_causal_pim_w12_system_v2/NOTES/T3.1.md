# T3.1 接口理解

- `scripts/run_proof_mainline.py` 在 dense retrieval 后构造
  `candidate_pool_records`：每个 demand 固定 48 个候选，包含 `base_record_id`、
  `object_ids`、`query_rank`、`retrieval_rank`、`retrieval_cosine` 和 rerank 后的
  `score`。
- witness 构造经 `validate_witnesses()` 过滤后保存在 `grounded_witnesses`。其
  `record_ids` 是发给 Reader 的短别名；`retrieval_record_ids` 才是 source record 身份。
- `source.json` 的 text object 直接带 `session_id`；image object 的 session 来自所有
  `sources[].session_id`。T3.1 直接读取这两个字段，不按文件名或路径猜测。
- `extensions.candidate_dump` 已由配置层解析，但此前未接入 serving。T3.1 不读取
  labels、question type、difficulty 或答案文件。

# T3.1 执行结果

## 实现

- 新增 `pim_backend/candidate_dump.py`。`build_candidate_dump()` 输出
  `omni-candidate-dump-v1`，每个 demand 必须恰有 48 个候选，并校验 retrieval rank
  从 0 连续、query rank 唯一、分数有限、record/object 身份存在。
- 每个候选输出 `record_id`、`object_ids`、`session_ids`、`modality`、
  `retrieval_cosine`、`rerank_score`、`query_rank`、`retrieval_rank`。`session_ids`
  是候选 object 集合在 source model 中的 session 并集；modality 只取 `text` 或
  `image`。
- 已接受见证输出 `witness_id`、`demand_id`、实际 `record_ids`、Reader 提议别名
  `proposal_record_ids`、`object_ids`、`base_record_id` 与 score。
- `write_candidate_dump()` 原子写入 `<dump>/<user>/<qid>.json`；目标已存在时拒绝覆盖。
- `run_proof_mainline.py` 在正常路径的 witness 校验后写 dump；as-of 模式下无可见历史时
  写空 demands/witnesses 文件，保持每题都有明确产物。
- dump 带 `label_free=true`、空的 `evaluation_label_files_read` 和边界说明；serving
  没有新增任何标签读取。

## 测试

- 定向测试：
  `pytest -q tests/test_candidate_dump.py tests/test_extensions_config.py tests/test_label_isolation.py`
  ，结果 `15 passed`。
- 覆盖固定 48 宽度、字段集合、text/image modality、image 多 source session 并集、
  见证原 record 身份、错误宽度、重复 retrieval rank、未知 object、非有限分数、原子写入
  与禁止覆盖。
- 完整 CPU：`pytest -q tests -m "not gpu"`，结果 `780 passed, 3 failed`。三个失败仍是
  既有基线：缺少 `artifacts/hyperpim_sc_trace_v1`、旧 judge 状态字符串、重复 demand
  预期差异。

- 在 RTX 3090 GPU 0 上运行单题 `1_q_104`（user 1），服务耗时 `700.63 s`，未使用
  GPU 2、4。运行目录为 `regression/golden_v2_t31_dump/run`，dump 为

- dump 标记 `split=development`、`label_free=true`、`candidate_width=48`、

- `d0` 的第一个 text 候选 session 为 `1_52_2`；一个 image 候选的 object session
  为 `1_31_4`。两个 accepted witness 均记录了实际 source record ids。
- `tools/regression_check.py regression/golden_v2_t24_shadow_trace regression/golden_v2_t31_dump/run`
  返回 `status=pass`、`failures=[]`、`nondeterministic_differences=[]`。

## 边界

- 本任务只导出候选和 accepted witness，不计算候选召回、校准或保形覆盖率。
- 候选宽度上限仍是 48；当某个 demand 不足 48 个候选时 fail closed，不填充或复制候选。
- dump 是离线校准输入，不改变检索、见证选择或最终答案路径。
