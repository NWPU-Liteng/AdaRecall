# T1.2 接口理解

- 运行目录的完整用户输出命名为 `user_<user>_shard_<n>.json`，同目录还有
  `user_<user>_shard_<n>.partial.json`。统计脚本只读取前者，并要求顶层 `complete=true`；
  不读取 partial、trace 或任何评测标签文件。
- `proof_status` 与 `selection_mode` 位于 `row.proof_plan`。query contract 的解析状态位于
  `row.proof_plan.query_parse.status`，`answer_mode` 位于 `row.proof_plan.query_contract`；
  旧输出若没有 query contract，则 answer mode 明确统计为 `missing`。
- join 成功路径的 `optimal`、`support_gap` 直接位于 `row.proof_plan`。进入非证明回退时，
  严格 join 的原结果保存在 `row.proof_plan.failed_strict_search`。脚本优先读取顶层结果，
  否则读取该对象。contextual 查询不需要正向合取证明，因此单独计入
  `not_applicable_contextual`，不混入 optimal 比例。
- 主 witness 校验拒绝项位于 `row.proof_plan.grounding.rejections`，每项含 `reason`。
  多见证影子路径还有 `multi_witness_shadow.rejections` 与 `search_rejections`；脚本分别按
  来源计数，避免把不同调用路径合并后失去来源。
- 上下文省略数量位于
  `row.proof_plan.grounding.omitted_whole_record_ids_due_to_context`。
- 最终证据预算记录在 `row.proof_plan.final_render`：
  `text_tokens`、`image_count`、`input_tokens`（processor token 数）。
- T1.1 的 `row.stage_profile.stages.<stage>.wall_ms` 是可选的；没有该字段的输出仍生成报告，
  并显式记录 missing 行数。
- 输出固定写到 `<run_dir>/run_stats.json` 与 `<run_dir>/run_stats.md`。markdown 使用单张
  `Section | Metric | Value` 表；JSON 保留完整计数和分布，分布给出 count/mean/P50/P90/min/max。
- 本任务不增加配置键，不改变 serving 行为，也不读取标签。
