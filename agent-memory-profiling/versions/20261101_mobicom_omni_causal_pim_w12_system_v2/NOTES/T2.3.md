# T2.3 接口理解

## v1 稠密检索选择规则

- `scripts/run_proof_mainline.py::main()` 在 `dense_retrieval` 阶段对每条
  `vectors.npy` 行执行 `vectors @ query`，再按 48 个候选构造 witness。
- 若 demand 的 `evidence_scope.kind` 为 `source_text` 或 `image_locator`，v1 先在该 kind
  内取 top-32，再用全体有限得分候选按分数补齐到 48；否则直接取全体 top-48。
- 未来不可见行在 mask 模式下先写成 `-inf`。filter 模式则复制可见向量，候选索引对应过滤
  后的 `records`，因此不能直接复用 base 行索引。
- `query_rank` 会被后续检索包逻辑用作当前 `records` 的下标，所以 filter 模式必须把
  base 量化选择结果映射回当前记录位置。

## 等价选择定理

- 全体 top-80 已覆盖最终 48 个候选中所有可能由全体榜单调入的记录；kind 内 top-32 已覆盖
  主选择所需记录。取两者并集后，在并集上重新执行 v1 的 32/48 规则，与全量计算后选择
  完全一致。
- 平局使用 `(-score, index)` 的稳定索引顺序；量化全量选择与渐进选择最后都使用同一个
  `reference_scores()` float64 路径。

# T2.3 执行结果

## 实现

- 扩展 `pim_backend/progressive_retrieval.py`：新增统一选择入口
  `select_dense_candidates()`、filter 行映射、shadow 全量一致性断言及按 demand 聚合。
- 用户索引加载后只调用一次 `quantize_plane_major(vectors, bits=12, group_size=128)`，
  不修改 v1 的 `vectors.npy` 或索引文件；统计中记录 `codes_sha256`。非 12/128 配置
  fail closed。
- `off` 模式继续使用 v1 的 32/48 选择，返回原始 float32 分数，`progressive_retrieval_stats`
  使用关闭态 summary。
- `shadow` 保留 v1 候选和 float32 分数；同时计算量化渐进选择与量化全量选择，断言索引和
  分数逐位相等，并记录量化候选与 float32 候选的 `overlap@48`。
- `replace` 使用量化渐进候选进入 rerank，分数改为同一量化参考路径的 float64 分数。
  该模式会改变实验输出，本次没有把它作为 golden 等价性结论运行。
- mask 模式把 replay/as-of 可见性直接作为量化矩阵 `row_mask`；filter 模式使用 base
  可见 mask，并通过 `index_map` 把选中 base 行映射为当前 `records` 下标。
- 顶层新增 `progressive_retrieval_stats`，包含 `codes_sha256`、逐 demand 的轮数、
  读取字节比例、`overlap@48`、精确性断言状态及总计。

## 边界

- 当前实现是 Host/NumPy 的 plane-major 量化参考路径，不声称已执行物理 bank-PIM，也不把
  本轮墙钟时间解释为 PIM 时延或能耗收益。
- shadow 的 `overlap@48` 衡量量化候选与 float32 候选的一致性，不保证量化解码后的分数与
  BF16 原始分数相同。
- replace 是改变结果的独立实验臂，须与关闭态和 shadow 分开报告。
