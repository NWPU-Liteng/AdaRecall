# M0 Pipeline Audit

This audit is based on the current repository files available on 2026-07-04. It is a pre-run inventory; formal MedMemoryBench execution remains blocked until official data are acquired and the schema audit is completed.

## Inventory Answers

1. **Qwen3-4B local model path or identifier**
   - Existing local generation clients resolve to `PROJECT_ROOT.parent / "dir"` in `agent-memory-profiling/experiments/motivation_memory_selection/profile_real_agent_v4.py`.
   - The generic client default is `LOCAL_QWEN_DIR` or `../dir` in `agent-memory-profiling/src/llm_client.py`.
   - The repository contains local model files under `dir/`, including `config.json`, tokenizer files, and three safetensor shards.

2. **Embedding model and reranker**
   - Embedding for the v4 real-agent pipeline uses `TransformerEmbeddingClient` from `agent-memory-profiling/src/embedding_client.py`, configured by `embedding_model_dir`.
   - The local available embedding model path is `agent-memory-profiling/models/bge-base-en-v1.5`.
   - Reranking uses `resolve_reranker_client` from `agent-memory-profiling/src/reranker_client.py`. Real reranking is `CrossEncoderRerankerClient`.
   - The local available cross-encoder path is `agent-memory-profiling/models/cross-encoder-ms-marco-MiniLM-L6-v2`.

3. **Candidate budget passed to ANN retrieval**
   - In `profile_real_agent_v4.py`, `retrieval_top_r` controls dense retrieval candidates, and `pruner_top_b` controls the reranker input frontier.
   - For v3, `frontier_budget` is defined as the reranker input frontier, with ANN overfetch controlled separately by `ann_top_r_multiplier`.

4. **Code paths for filter, dedup, materialization, rerank, final top-K**
   - v4 runtime candidate filtering by visible memory IDs: `profile_real_agent_v4.py`, main loop over `memory_ids_available`.
   - Dense retrieval: `_dense_retrieve`.
   - Reranker materialization and scoring: `_run_selection`, `reranker_client.score_pairs`.
   - Final top-K selection: `_run_selection`, `reranked[:final_top_k]`.
   - v3 implements the corresponding MedMemoryBench path in `scripts/medmmb_common.py`.

5. **Does frontier_budget cap ANN candidates, reranker inputs, or both?**
   - In the old v4 terminology, `pruner_top_b` caps reranker inputs; `retrieval_top_r` caps dense ANN candidates.
   - In v3, `frontier_budget` caps reranker inputs. ANN candidates are requested as `max(frontier_budget * ann_top_r_multiplier, frontier_budget)`.

6. **Is final_top_k=5 always reachable?**
   - Not always. It requires at least five eligible pre-query memory items after persona/session filtering and at least five candidates reaching rerank.
   - v3 marks under-filled formal budget points as ineligible or fails where the instruction requires fail-fast behavior.

7. **True reranker or embedding similarity**
   - `CrossEncoderRerankerClient` is a true sequence-classification reranker when configured with a valid sequence-classification model.
   - `HeuristicRerankerClient` only forwards vector similarity and is not acceptable for formal v3 runs.
   - v3 config defaults to the local cross-encoder path and rejects heuristic formal runs.

8. **GPU synchronizations for timing**
   - v4 uses `_cuda_sync()` before and after `_time_call`.
   - v3 uses the same synchronization pattern in `scripts/medmmb_common.py` for embedding, ANN, rerank, controller intent generation, and answer generation timing.

9. **Prompt leakage risk**
   - v4 prompts use selected memory text and timestamps; labels are loaded separately from `evaluation_labels.jsonl`.
   - v3 prompt builders only admit query text, query type, session index/date, stage instructions, prior controller summaries, selected memory text, and permitted metadata.
   - v3 explicitly excludes `answers`, `source_key_points`, `knowledge_points`, event labels, future sessions, and event details that reveal answers from prompts.

10. **Answer/scoring post-processing**
   - Existing post-processing is in `agent-memory-profiling/experiments/motivation_memory_selection/qa_eval_utils.py`: `extract_final_answer`, normalization, exact match, token F1, and contains-reference checks.
   - v3 preserves `answer_raw` and writes deterministic `answer_normalized` separately. It does not rewrite generated answers based on references.
